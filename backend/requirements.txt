# EVAC-120 backend — Phase 0 baseline.
# Deliberately minimal. Every addition must be flagged and justified: this runs
# on a site edge node that must work with zero Internet.

# --- Phase 0/1: pure-Python core, vendored identity code, simulator, tests ---
numpy==2.2.1            # vendor/deepstream/recognition.py Gallery matmul
pytest==8.3.4
pytest-cov==6.0.0
hypothesis==6.122.3     # Phase 1 property tests ("no injection yields ACCOUNTED
                        # without qualifying evidence")

# --- Phase 4: the API surface ---
# FastAPI earns its place by generating the OpenAPI spec the brief requires and
# by validating request bodies at the boundary, which is where a malformed
# warden action should be rejected rather than three layers in. It is also the
# stack VisionTrack already runs, so the deployment story is familiar.
fastapi==0.115.6
uvicorn[standard]==0.34.0
httpx==0.28.1           # test client only

# --- Persistence ---
# The brief sanctions Alembic for schema, and Alembic requires SQLAlchemy.
# Core rather than the ORM: the schema is small and explicit, and an event log
# is a poor fit for object mapping. Sync rather than async, because the edge
# process is a scheduling loop and the API can hand a blocking call to a thread
# far more cheaply than the whole codebase can become async.
sqlalchemy==2.0.36
alembic==1.14.0
psycopg2-binary==2.9.10

# --- Authentication ---
# A library rather than 80 lines of hmac. JWT has a well-known set of ways to
# get it wrong — accepting `alg: none`, algorithm confusion between HS256 and
# RS256, forgetting to check expiry — and "we wrote our own" is not a sentence
# worth having in a security review of a life-safety-adjacent system. The
# fewer-dependencies argument for an edge node does not outweigh that.
pyjwt==2.10.1
